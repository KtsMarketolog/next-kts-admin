# Почтовые снимки персональных дашбордов

Обработчик предназначен для всех вложений `.ktsp`, включая письмо с 11 файлами
для разных менеджеров. Он открывает `INBOX` только для чтения: не меняет флаги,
не помечает письма прочитанными, не создаёт папки, не перемещает и не удаляет письма.
Импорт остатков работает отдельно; его код и расписание не изменяются.

## Включение после определения отправителя

По умолчанию обработчик выключен. До согласования точного адреса отправителя
переменную включения и cron не устанавливать. Эти файлы — подготовка конфигурации,
они не устанавливают cron и не включают импорт автоматически.

В закрытом окружении приложения нужны:

```dotenv
MANAGER_DASHBOARD_MAIL_ENABLED=false
MANAGER_DASHBOARD_MAIL_ALLOWED_FROM=
MANAGER_DASHBOARD_MAIL_SCAN_LIMIT=300
MANAGER_DASHBOARD_MAIL_LOOKBACK_DAYS=14
```

После согласования `MANAGER_DASHBOARD_MAIL_ALLOWED_FROM` содержит один точный
адрес либо несколько адресов через запятую; затем `MANAGER_DASHBOARD_MAIL_ENABLED=true`.
Без явного корректного списка отправителей почта и база не открываются, даже
если включение указано. Шаблоны доменов и отображаемые имена не поддерживаются.
Из поля `From` допускается ровно один адрес, совпадающий со списком. Отправитель
из настроек остатков, встроенные адреса и собственный адрес ящика не добавляются.
Вложенные пересланные письма `message/rfc822` не разбираются от имени внешнего
отправителя. Проверка `From` сама по себе не является криптографической проверкой
автора: настройки SPF/DKIM/DMARC и фильтрацию поддельных писем обеспечивает почтовый
провайдер. Поле `Authentication-Results` из произвольного письма не считается
доверенным доказательством.

Отдельные `MANAGER_DASHBOARD_MAIL_HOST`, `_PORT`, `_SECURE`, `_USER`, `_PASSWORD`
необязательны. Для каждого поля используется соответствующее `STOCK_MAIL_*`,
затем `SMTP_USER` / `SMTP_PASSWORD` / `SMTP_PASS`; SMTP-host преобразуется в IMAP-host
заменой `smtp.` на `imap.`. Host по умолчанию `imap.yandex.ru`, порт 993, TLS включён.
При `_SECURE=false` обязателен STARTTLS. Пароли и `CRON_SECRET` хранить только в
закрытом env; не передавать в URL, командной строке или логах.

Проверенное до внедрения подключение остатков на production:
`STOCK_MAIL_HOST=imap.mail.ru`, `STOCK_MAIL_USER=info@kts-impex.ru`.
Это факт чтения конфигурации, а не выполненная проверка почтового сервера.

## Чтение и повторные письма

Просматриваются последние 300 писем (настройка от 1 до 1000), включая прочитанные,
с датой поступления на сервер не старше 14 дней (настройка от 1 до 14).
Заголовок `Date` не используется для определения свежести почты. Выгружаются
метаданные писем, после окончания FETCH — отдельные вложения потоком. Все подходящие
вложения рассматриваются, ошибка одного файла не отменяет остальные.

Размер письма ограничен 64 МиБ, декодированного `.ktsp` — 8 МиБ. Если письмо
превышает предел, его файлы не скачиваются. Превышение размера вложения определяется
также по реально прочитанным байтам, независимо от MIME-метаданных.

Для источника сохраняется SHA-256 от идентичности ящика, UIDVALIDITY, UID, MIME-части
и SHA-256 содержимого. Повторная обработка не создаёт новый снимок. Менеджер, срок действия,
формат, дата данных и конфликты проверяются в общей функции импорта снимков;
валидный файл публикуется только после её проверок. На весь цикл, включая чтение
почты, действует session advisory lock PostgreSQL. Параллельная проверка возвращает
`busy`; сбой процесса освобождает блокировку при закрытии соединения.

Почтовые вложения хранятся в исходном ящике, а журнал полученных файлов — в
приложении. Ошибки скачивания и превышения почтовых лимитов записываются отдельными
записями в журнал импорта и возвращаются в результате проверки. Для них используется
идентичность части письма и код ошибки, без хеша недоступного содержимого. Повторная
проверка может заново скачать файл после временного сбоя. Содержимое
ошибочных файлов в почтовые логи не выводится. Ответ содержит до 200 подробных
результатов, суммарные счётчики охватывают все рассмотренные вложения.

Файлы остатков `.xlsx` и персональные `.ktsp` следует отправлять **разными письмами**:
действующий импорт остатков перемещает всё письмо. Этот обработчик читает только
INBOX и не восстанавливает письма, перемещённые другим процессом. Если в ящике более
300 новых писем между проверками, увеличьте допустимый предел или частоту проверки;
это сканирование окна, а не гарантия чтения всей истории ящика.

## Предлагаемое расписание, ещё не установлено

Для сервера с `Etc/UTC` следующие строки соответствуют Москве: ежедневно
07:00–11:55 каждые пять минут, затем 12:00–18:00 каждый час. Их необходимо отдельно
добавить в существующий пользовательский crontab после согласования отправителя;
не заменять существующие строки и не менять расписание импорта остатков.
Пути Node и приложения сверить перед установкой.

```cron
*/5 4-8 * * * /usr/bin/node --env-file=/home/kts/kts-next-admin/.env.local /home/kts/kts-next-admin/current/ops/manager-dashboard/check-email.cjs >> /home/kts/kts-next-admin/shared/logs/manager-dashboard-mail.log 2>&1
0 9-15 * * * /usr/bin/node --env-file=/home/kts/kts-next-admin/.env.local /home/kts/kts-next-admin/current/ops/manager-dashboard/check-email.cjs >> /home/kts/kts-next-admin/shared/logs/manager-dashboard-mail.log 2>&1
```

Проверка раз в пять минут не гарантирует отображение письма, поступившего ровно
в 10:00, уже к 10:00. Для готовности дашборда к этому часу отправку следует
завершать раньше с запасом на доставку и обработку. Дата снимка и отсутствие
сегодняшнего обновления должны быть видны в кабинете.

После включения ручная проверка использует защищённый административный API.
Cron-обёртка обращается только к локальному `POST /api/cron/manager-dashboard-import`
с Bearer `CRON_SECRET`, не печатает его и не использует внешний URL. Для разработки
предусмотрен `scripts/import-manager-snapshots.ts`; его запуск действительно
открывает почту и импортирует данные, поэтому не использовать для проверки сборки.

## Изолированная браузерная проверка

Отдельный необязательный тест не входит в `npm test` и не подключается к базе,
почте или production. Он читает исходный HTML только для чтения, создаёт полностью
синтетический зашифрованный `.ktsp` в памяти и временный HTTP-сервер на `127.0.0.1`
со случайным портом. Частные вложения не копируются в репозиторий. Внешние запросы
браузера блокируются. Проверяются Chromium и WebKit, если их исполняемые файлы
установлены; сервер и браузеры закрываются также при ошибке.

```bash
INPUT_PERSONAL_HTML='/path/to/personal-v12.html' \
PLAYWRIGHT_MODULE_PATH='/path/to/node_modules/playwright' \
node --import tsx tests/manager-dashboard-browser.integration.ts
```

При отсутствии `PLAYWRIGHT_MODULE_PATH` используется локальный пакет Playwright
или bundled runtime Codex на этой рабочей станции. При отсутствии
`INPUT_PERSONAL_HTML` тест явно сообщает о пропуске. Тест сравнивает поставленный
v12 и встроенную версию на одних синтетических строках: пароль, расшифровка,
контрольные суммы, KPI, месяцы, вкладки и разрезы, ограничения iframe и экспорт XLSX
после реального клика пользователя. Он не заменяет проверки разграничения доступа
к API и базе данных.
