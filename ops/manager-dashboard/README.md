# Снимки дашбордов: только ручная загрузка

Снимки загружаются администратором на странице `/admin/manager-dashboard`.
Загрузка HTML и публикация HTML выполняются отдельно от загрузки данных.

Импорт снимков дашбордов из почты отключён в коде. Старые значения
`MANAGER_DASHBOARD_MAIL_ENABLED=true` и других `MANAGER_DASHBOARD_MAIL_*`
не включают его: обработчик не читает почтовые пароли, не подключается к IMAP
или базе, не меняет журнал импорта и сохранённые почтовые отметки.
Административный endpoint `POST /api/admin/manager-dashboard/check-email`
после проверки доступа возвращает `410 MANUAL_UPLOAD_ONLY`.

Импорт остатков, его почтовая конфигурация, расписание, SMTP и рассылки приложения
работают отдельно. Для перехода на ручную загрузку их настройки менять не нужно.

## Старые команды

`install-mail.cjs configure` и `install-mail.cjs schedule` больше ничего
не устанавливают и возвращают `disabled / manual_only`.
`check-email.cjs` и `scripts/import-manager-snapshots.ts` сообщают об отключении
и завершаются без почтовых запросов. Они оставлены как безопасные точки входа
для старых команд.

Постоянная копия старой обёртки в `shared/bin` не обновляется вместе со
standalone-релизом. Её прежнее расписание нужно снять отдельным шагом ниже.
Даже если старая обёртка будет запущена вручную, обновлённый сервер не импортирует
снимки из почты.

## Снятие прежнего расписания на production

Утилита `disable-mail.cjs` изменяет только crontab пользователя `kts`.
Она удаляет блок между точными маркерами:

```text
# BEGIN KTS PERSONAL MANAGER DASHBOARD MAIL
# END KTS PERSONAL MANAGER DASHBOARD MAIL
```

Внутри допускаются только комментарии, пустые строки и две прежние команды
проверки дашбордов, установленные этим проектом. Неизвестная команда или
повреждённые/повторные маркеры приводят к отказу без изменения crontab.
Вне блока сохраняется каждый байт, включая импорт остатков, уведомления,
настройки часового пояса и комментарии. Задания дашбордов вне блока только
учитываются в `unmanagedDashboardJobs`; автоматически они не удаляются.

Папка `ops` не входит в standalone-артефакт. Перед деплоем скопируйте проверенный
`disable-mail.cjs` в приватный временный каталог production-сервера и выполните
от пользователя `kts`:

```bash
/usr/bin/node /проверенный/каталог/disable-mail.cjs --dry-run
/usr/bin/node /проверенный/каталог/disable-mail.cjs --apply
```

`--dry-run` только читает crontab и показывает, найден ли блок; файлов не создаёт.
`--apply` сначала сохраняет точную резервную копию crontab в отдельном приватном
временном каталоге (700, файл 600), проверяет отсутствие параллельных изменений,
удаляет свой блок и перечитывает результат. Путь к резервной копии возвращается
в поле `backup`. Повторный запуск без блока ничего не меняет.

Затем выполните штатный деплой версии приложения с ручной загрузкой.
Удаление cron не останавливает уже выполняющийся процесс старого релиза;
убедитесь, что начатая до переключения проверка завершилась. Эта утилита
не останавливает процессы, не перезапускает приложение и не редактирует env.
Она не удаляет снимки, HTML, журнал импорта, почтовые отметки или письма.

## Изолированные проверки

Регрессионные тесты подтверждают постоянное отключение даже со старыми включёнными
настройками, отсутствие чтения секретов/сети/базы, защищённый ответ 410,
сохранность посторонних cron-строк и идемпотентность очистки. Они не обращаются
к production, почте или реальному crontab:

```bash
node --import tsx --test tests/manager-dashboard-mail.test.ts tests/manager-dashboard-check-email.test.ts tests/manager-dashboard-install.test.ts
```
