# Курсы валют: серверные источники и база меди

Код не устанавливает расписание автоматически и не изменяет действующие задания
импорта/резервного копирования. Для фиксации базы без открытого браузера после
выкладки приложения необходимо один раз установить отдельный timer ниже.

## Размещение и обновление HTML

Раздел находится в каталоге «HTML-страницы и отчёты» по адресу
`/admin/top/currency-rates`. Чтение и изменение доступны только действующим
серверным сессиям `admin` и `admintop`. Это отдельный системный отчёт: обычные TOP,
менеджеры и закупщики не получают доступ через права на другие HTML-блоки.

Адаптированный авторский V21 хранится в
`assets/currency-dashboard/kursy_valyut_v21.html`, вне публичного каталога.
Он включается в standalone-релиз через `outputFileTracingIncludes` и выдаётся
только защищённым frame endpoint. Окно изолировано без `allow-same-origin` и
без прямых сетевых запросов. Узкий мост сообщает серверу только разрешённые
действия; каждый запрос заново проверяет роль, а запись — Origin и ревизию.

Новый HTML автора нельзя просто загрузить в обычный TOP-блок и ожидать такую же
серверную интеграцию. Обновление этого отчёта выполняется заменой проверенного
HTML в коде с сохранением RPC-контракта, месячного фильтра, проверок ввода и
защитного адаптера. Новую авторскую версию сначала адаптировать и проверить,
затем выпускать обычным деплоем. Общая защита остальных HTML-отчётов не ослаблена.

Ручные курсы, прогнозы, премия и ручные цены меди сохраняются общими. Устройства
обновляют их раз в минуту и при возврате на вкладку. Конфликт параллельной правки
не перезаписывает сервер: администратор получает предупреждение и обновляет
актуальный снимок. Снимок с неподтверждённым сохранением не объявляется успешным.
При откате сохраняется заменённая текущая версия; остаются ровно два состояния.
Настройки звука и переключения вкладок не переносятся другому администратору.

Проверки перед выпуском:

```bash
npm test
npx tsc --noEmit --incremental false
npm run lint
npm run build:webpack
node --import tsx tests/currency-dashboard.browser.integration.ts
```

Браузерная проверка использует локальный сервер и синтетические данные, не
публикует файлы клиента. Отдельный тест
`tests/currency-dashboard-repo.postgres.test.ts` включается только при явных
`KTS_CURRENCY_POSTGRES_TEST=1` и `KTS_CURRENCY_TEST_DATABASE_URL` для временной
socket-only базы `kts_currency_integration` (проверки имени/пути внутри теста).
Обычный `DATABASE_URL` этот тест не использует.

## Источники и время

- ЦБ: официальный XML API, дневные USD/EUR/CNY/KZT и история с 01.01.2026.
  Номинал сохраняется; цена 100 KZT не превращается в цену 1 KZT.
- Мосбиржа: публичный ISS для валют, COPPER и BR. **Это данные с задержкой до
  15 минут, не поток реального времени.** Цена COPPER котируется в USD за тонну,
  BR — в USD за баррель. Рублёвые расчёты по контракту не меняют единицу котировки.
- Мировые кросс-курсы: ExchangeRate-API, обновление источника обычно раз в сутки.
- Официальные Cash Settlement/3-month: таблица Westmetall, не внутридневной fx678.

Публичные источники: [ЦБ XML](https://www.cbr.ru/development/SXML/),
[ISS и задержка](https://www.moex.com/a8589),
[единица COPPER](https://www.moex.com/ru/derivatives/futures-on-commodity/ceu6),
[условия ISS](https://www.moex.com/a2193).
Для использования биржевых данных в реальном времени требуется отдельный
источник/подписка; допустимый способ использования данных нужно проверить по
договору организации с поставщиком. Реализация не заявляет наличие подписки.

Timer запускает POST `/api/cron/currency-dashboard` каждые 5 минут. Источники имеют
свои TTL, поэтому ЦБ/медь/мировые валюты не запрашиваются каждые 5 минут без нужды.
В 08:30 МСК фьючерсы обновляются принудительно, а сервер сохраняет доступную в этот
момент цену, идентификатор контракта, реальное время фиксации, время последней
сделки (если известно), признак устаревания и действовавшую премию Jintian.
В течение дня сравнивается тот же контракт, а не случайно выбранный новый.

При отсутствии сделок допускается предыдущая расчётная цена с явной пометкой,
без выдуманного времени котировки. Последняя удачная загрузка не получает новое
время после ошибки. Недоступный источник возвращается как устаревший кэш.

Фиксация допустима только в минуту **08:30:00–08:30:59 МСК**. Если сервер/источник
был недоступен, более поздняя цена не записывается задним числом как 08:30.
Состояние `missed`/`unavailable` видно в результате задания и в журнале systemd.
Нужен контроль этого журнала штатным мониторингом. Повторный запуск не меняет
уже зафиксированную базу; блокировка PostgreSQL действует на оба процесса PM2.

## Установка на существующем VPS (пользовательский systemd)

Используется **существующий пользователь `kts`**, его user-systemd и включённый
`Linger=yes`: задание работает без SSH-сессии. Root, sudo и новый пользователь не
нужны. Проверка до установки: `loginctl show-user kts -p Linger` и
`systemctl --user is-system-running`. В unit нет `User=`/`Group=`; `%h` раскрывает
домашний каталог пользователя, а `/usr/bin/node` должен поддерживать `fetch`.

Из проверенного полного checkout, содержащего `ops` и `scripts`, под `kts`:

```bash
node ops/currency-dashboard/install.mjs --app-env /home/kts/kts-next-admin/.env.local --dry-run
node ops/currency-dashboard/install.mjs --app-env /home/kts/kts-next-admin/.env.local --apply
```

Без `--apply` скрипт только читает и показывает точные пути планируемых изменений.
`--home` предназначен для локальных временных тестов или явно другого домашнего
каталога; на этом VPS его указывать не требуется.

При применении установщик:

- использует существующий `CURRENCY_DASHBOARD_CRON_SECRET` либо создаёт отдельный
  случайный 64-символьный секрет и согласованно добавляет его в точный app-env и
  `~/.config/kts-currency-dashboard.env` (оба файла `600`);
- не выводит секрет; отказывает при дубликатах, несовпадающих секретах,
  неожиданных ссылках/владельцах/правах и изменении файла во время установки;
- сохраняет остальные байты env, копирует caller в
  `~/.local/lib/kts-currency-dashboard/refresh.mjs` (`700`), unit-файлы — в
  `~/.config/systemd/user/` (`600`);
- до записи делает резервные копии заменяемых файлов в приватном каталоге
  `~/.local/state/kts-currency-dashboard/backups/install-*` (`700`, файлы `600`).
  Эти копии содержат прежние env: не публиковать и не пересылать их;
- **не перезапускает приложение, не вызывает systemctl и не включает timer**.

Повторный запуск с неизменными файлами ничего не переписывает. Скрипт/units лежат
вне сменяемых standalone-релизов; при обновлении запускать проверенный установщик
повторно. Если запись оборвалась, сервер/расписание сами не перезапускаются;
проверить итог и повторить установку либо восстановить конкретный файл из
указанной резервной копии. Другие задания не затрагиваются.

После успешного деплоя **и перезагрузки приложения с новым app-env**:

```bash
systemctl --user daemon-reload
systemctl --user start kts-currency-dashboard.service
systemctl --user enable --now kts-currency-dashboard.timer
systemctl --user list-timers kts-currency-dashboard.timer
journalctl --user -u kts-currency-dashboard.service -n 30 --no-pager
```

Первый ручной запуск после 08:30 без ранее записанной базы честно вернёт `missed`;
история и текущие источники при этом загружаются. Первая штатная база появится
при следующем успешном запуске в 08:30. Проверить утром `captured`, две строки
базы и отсутствие повторной записи при повторном запуске.

Остановка (не удаляет данные):

```bash
systemctl --user disable --now kts-currency-dashboard.timer
```

Текущий и предыдущий **ручные снимки** хранятся отдельно от истории ЦБ, архивных
баз меди и последнего успешного ответа источников. Ограничение «две версии» не
удаляет ретроспективные валютные курсы.
