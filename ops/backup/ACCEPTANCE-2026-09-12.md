## Выявленные особенности

На этом бакете явные SSE-заголовки запроса возвращали AccessDenied; загрузка
через настроенное KMS-шифрование бакета прошла. Права не расширялись.
Теперь перед каждым PUT проверяется точная настройка default KMS, затем actual
HEAD/KMS и скачанные байты. Администратор не должен менять шифрование во время PUT:
эти операции не атомарны. Runtime не может изменить настройку бакета.

Яндекс возвращает `Metadata.Sha256`. Все пути, включая cloud restore, используют
строгий регистронезависимый разбор имени; неоднозначные дубли отвергаются.

Первый запуск без linger был остановлен при завершении SSH-сессии. После включения
linger повторная служба отработала полностью. Удалён ровно один подтверждённый
собственный временный partial dump (109338624 байта), не готовая копия.
