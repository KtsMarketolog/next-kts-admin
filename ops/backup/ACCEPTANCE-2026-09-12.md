## Выявленные особенности

На этом бакете явные SSE-заголовки запроса возвращали AccessDenied; загрузка
через настроенное KMS-шифрование бакета прошла. Права не расширялись.
Теперь перед каждым PUT проверяется точная настройка default KMS, затем actual
HEAD/KMS и скачанные байты. Администратор не должен менять шифрование во время PUT:
эти операции не атомарны. Runtime не может изменить настройку бакета.

Яндекс возвращает `Metadata.Sha256`. Все пути, включая cloud restore, используют
строгий регистронезависимый разбор имени; неоднозначные дубли отвергаются.

Первый запуск без linger был остановлен при завершении SSH-сессии. После включения
linger повторная служба отработала полностью. Удалён ровно один подтверждённый
собственный временный partial dump (109338624 байта), не готовая копия.

## Эксплуатация и ограничения

Обязательных ручных действий для запуска больше нет. Расписания опубликованы:
ежедневный бэкап 02:15 UTC, независимый check 03:45 UTC, облачное восстановление
по воскресеньям 04:30 UTC. Во время приёмки первый плановый запуск ещё не наступил;
создание копии, обе разновидности проверки и доставка писем испытаны вручную.
GitHub может задерживать cron; контроль допускает возраст копии до 30 часов.

Тестовую ветку не сливать в main и не использовать как рабочую конфигурацию.
Плановые запуски используют main, где адрес production не заменён.
В независимом письме старого шаблона строка «последний успешный локальный бэкап:
не подтверждена» означает, что отдельный отправитель не обращается к VPS;
это не утверждение об отсутствии исправных копий. Результат проверки — по ссылке
на соответствующий GitHub run.

Хранить аварийные доступы к GitHub, серверу, Yandex Cloud и KMS вне этого сервера.
Не удалять KMS-ключ. Backup не включает весь ОС-образ, а 5 дней облачного хранения
не дают 14-дневной истории при потере VPS. При длительном отказе облака или нехватке
места реагировать на письма; автоматически удалять неподтверждённые копии нельзя.

Полные команды и инструкция аварийного восстановления находятся в `README.md`;
подключение независимого email — в `MONITORING.md`.
