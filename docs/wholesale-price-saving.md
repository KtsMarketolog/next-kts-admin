# Сохранение индивидуальных прайсов

## Исправление 14 сентября 2026

Редактор отправляет весь каталог, включая выключенные позиции. Раньше создание
и обновление сохраняли только первые 5 000 строк запроса без сообщения об ошибке.
При повторном открытии остальные товары возвращались как выключенные, без
сохранённых скидок и ручных цен. В каталоге из 7 474 товаров это, в частности,
оставляло 323 из 659 товаров группы «Carel увлажнение».

Теперь оба API используют общий валидатор без ограничения на число строк:

- Все переданные корректные позиции сохраняются, включая выключенные.
- Некорректные или повторяющиеся позиции отклоняют весь запрос, а не пропускаются.
- Для защиты памяти JSON ограничен 16 МиБ фактически прочитанных байтов. При
  превышении возвращается HTTP 413 до записи, даже если Content-Length отсутствует
  или неверно занижен. Это ограничение размера запроса, не числа товаров.
- Заголовок прайса, его позиции, настройки остатков групп и событие изменения
  записываются в одной транзакции. Ошибка откатывает все эти изменения.
- Позиции записываются пакетами, без отдельного запроса на каждый товар. Удалённый
  товар или неверный вариант приводит к ошибке и откату, а не частичному сохранению.
- Обновления одного прайса сериализуются блокировкой строки. Это не объединение
  правок: последняя успешно сохранённая версия остаётся итоговой.

Формулы цен, расчёт скидок и права доступа не изменены. Миграция схемы не нужна.

### Сохранение уже открытой корзины

При последующем исправлении по аудиту запись позиций заменена на согласование
по паре «товар + вариант». Существующие позиции обновляются с прежними ID,
`created_at` и полями снимка; новые получают новые ID. Это сохраняет пригодность
уже открытой клиентом корзины при обычном пересохранении прайса.

Сам прайс и его публичный token не удаляются/пересоздаются. Удаляются только
позиции, действительно отсутствующие в переданном составе при сохранении этого
прайса; скрытые позиции, присутствующие в запросе, сохраняются. Если выбранный
товар действительно убран или скрыт менеджером, заявка с ним по-прежнему
отклоняется, но интерфейс сообщает об изменении состава, а не о проблеме интернета.

Исторические дубликаты пары «товар + вариант», если они есть, не удаляются
автоматически: сохранение такого прайса отклоняется до изменений для отдельной
проверки администратором. Предустановленной массовой переработки прайсов нет.

## Ранее сохранённые прайсы

Исправление не включает автоматически товары, выбор которых прежний код потерял:
невозможно отличить ранее потерянный выбор от намеренно выключенной позиции.
Нужно снова выбрать нужные группы/позиции, при необходимости назначить скидки
или ручные цены, сохранить и повторно открыть прайс. Уже сохранённые значения
существующих строк сохраняются по прежним правилам редактора.

## Проверка

`npm test` проверяет большие массивы позиций, значения за старой границей,
дубликаты, некорректные строки, JSON и размер потока. Изолированные PostgreSQL
проверки используют только временный кластер с Unix-сокетом, синтетические данные
и отдельную непривилегированную роль. Не запускать интеграционные проверки с
production DATABASE_URL и не сохранять рабочий клиентский прайс ради проверки.

Запуск изолированного теста на машине с PostgreSQL 16:

```sh
bash scripts/test-wholesale-price-postgres.sh
```

Проверено на PostgreSQL 16.15: создание 7 475 строк, обновление до 20 001,
повторное чтение, публичный прайс, поздние скидки/ручные цены, откат неверного
товара/варианта, откат неуспешного создания и два параллельных сохранения.
