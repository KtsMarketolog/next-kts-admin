# Сохранение индивидуальных прайсов

## Исправление 14 сентября 2026

Редактор отправляет весь каталог, включая выключенные позиции. Раньше создание
и обновление сохраняли только первые 5 000 строк запроса без сообщения об ошибке.
При повторном открытии остальные товары возвращались как выключенные, без
сохранённых скидок и ручных цен. В каталоге из 7 474 товаров это, в частности,
оставляло 323 из 659 товаров группы «Carel увлажнение».

Теперь оба API используют общий валидатор без ограничения на число строк:

- Все переданные корректные позиции сохраняются, включая выключенные.
- Некорректные или повторяющиеся позиции отклоняют весь запрос, а не пропускаются.
- Для защиты памяти JSON ограничен 16 МиБ фактически прочитанных байтов. При
  превышении возвращается HTTP 413 до записи, даже если Content-Length отсутствует
  или неверно занижен. Это ограничение размера запроса, не числа товаров.
- Заголовок прайса, его позиции, настройки остатков групп и событие изменения
  записываются в одной транзакции. Ошибка откатывает все эти изменения.
- Позиции записываются пакетами, без отдельного запроса на каждый товар. Удалённый
  товар или неверный вариант приводит к ошибке и откату, а не частичному сохранению.
- Обновления одного прайса сериализуются блокировкой строки. Для переданных
  позиций последняя успешно сохранённая правка остаётся итоговой; отсутствующие
  в запросе позиции сохраняют прежнее состояние.

Формулы цен, расчёт скидок и права доступа не изменены. Миграция схемы не нужна.

### Сохранение уже открытой корзины

При последующем исправлении по аудиту запись позиций заменена на согласование
по паре «товар + вариант». Существующие позиции обновляются с прежними ID,
`created_at` и полями снимка; новые получают новые ID. Это сохраняет пригодность
уже открытой клиентом корзины при обычном пересохранении прайса.

Сам прайс и его публичный token не удаляются/пересоздаются. Сохранение больше
не удаляет позиции, отсутствующие в запросе: это может быть неполный каталог,
а не намерение пользователя. Чтобы убрать товар из публичного прайса, менеджер
явно выключает его (`visible: false`); строка и её индивидуальные настройки
остаются сохранены. Заявка со скрытым товаром по-прежнему отклоняется, но
интерфейс сообщает об изменении состава, а не о проблеме интернета.

Исторические дубликаты пары «товар + вариант», если они есть, не удаляются
автоматически: сохранение такого прайса отклоняется до изменений для отдельной
проверки администратором. Предустановленной массовой переработки прайсов нет.

### Защита при ошибке загрузки каталога — 18 октября 2026

Редактор отличает успешный ответ с пустым каталогом от ошибки или неполного
ответа. До успешной загрузки необходимых данных сохранение недоступно; ошибка
не превращается в пустой список позиций. Сохранённые позиции, отсутствующие в
активном каталоге, хранятся отдельно от отображаемых строк и не теряют свои
настройки при работе с видимыми группами и товарами. При сохранении отправляются
только ключи активного каталога; недоступные позиции остаются в модели редактора,
но не пересылаются и не перезаписываются. Это сохраняет побайтно их строки в БД,
включая исторические цены без современных признаков ручной цены/скидки, и не
затирает параллельные изменения недоступных товаров устаревшей копией редактора.

На сервере действует независимая защита: список `items` — набор обновляемых
ключей «товар + вариант», не полный состав для удаления отсутствующих строк.
Даже пустой или неполный массив из старого клиента не очищает позиции. Отсутствие
самого массива и некорректные строки отклоняются прежним валидатором. Обновление
полей карточки при пустом массиве не меняет строки позиций, включая их `updated_at`.

Неактивные товары и варианты не показываются в публичном прайсе, но сохраняют
выбор, ручные цены, скидки, порядок, ID и поля снимка. После их возвращения в
каталог действуют прежние сохранённые настройки. События добавления/удаления
позиций считают изменение фактического сохранённого `visible`, а не размер
пришедшего массива: пропуск строк не создаёт ложное событие удаления.

Настройки остатков ценовых групп по-прежнему сохраняются целиком: редактор
удерживает полный сохранённый набор, включая группы вне активного каталога.
Это оставляет явное выключение настройки группы работающим. Права доступа,
транзакции и формулы цен не изменены. Существующие данные не переписываются;
исправление не восстанавливает автоматически позиции, уже удалённые старым кодом.

## Ранее сохранённые прайсы

### Назначение менеджеров при сохранении

Сохранение прайса и выбранных менеджеров в его карточке клиента выполняется
одной транзакцией. Внутри неё проверяются роли и активность обоих менеджеров,
активность и доступность компании; строки блокируются до завершения операции.
Ошибка назначения, записи компании или позиции откатывает весь запрос, включая
создание нового прайса и его событие. Это устраняет частичное создание с ответом
400; не является общей гарантией идемпотентности при потере HTTP-ответа в сети.

Уведомление интерфейсов выполняется после commit. Его отдельная ошибка не
превращает уже сохранённый прайс в ошибку сохранения. Другие прайсы компании
не переписываются; миграции, массового переназначения и удаления старых прайсов нет.

### Прежний потерянный выбор товаров

Исправление не включает автоматически товары, выбор которых прежний код потерял:
невозможно отличить ранее потерянный выбор от намеренно выключенной позиции.
Нужно снова выбрать нужные группы/позиции, при необходимости назначить скидки
или ручные цены, сохранить и повторно открыть прайс. Уже сохранённые значения
существующих строк сохраняются по прежним правилам редактора.

## Проверка

`npm test` проверяет большие массивы позиций, значения за старой границей,
дубликаты, некорректные строки, JSON и размер потока. Изолированные PostgreSQL
проверки используют только временный кластер с Unix-сокетом, синтетические данные
и отдельную непривилегированную роль. Не запускать интеграционные проверки с
production DATABASE_URL и не сохранять рабочий клиентский прайс ради проверки.

Запуск изолированного теста на машине с PostgreSQL 16:

```sh
bash scripts/test-wholesale-price-postgres.sh
```

Браузерная регрессия реального редактора (Chromium/WebKit, только синтетические
HTTP-ответы; нужен установленный Playwright):

```sh
node --import tsx tests/wholesale-price-editor.browser.integration.ts
```

Проверяются ошибки HTTP/сети/JSON, неполные ответы, постоянное сообщение об ошибке,
повторная загрузка, таймаут, успешный пустой каталог и поздние ответы после смены
прайса. Неактивные ключи не отправляются даже при массовом скрытии или расчёте
скидки; ошибка сохранения не теряет введённые значения и освобождает кнопку.

Проверки охватывают создание 7 475 строк, обновление до 20 001,
повторное чтение, публичный прайс, поздние скидки/ручные цены, откат неверного
товара/варианта, откат неуспешного создания и два параллельных сохранения.
Регрессии пустого/неполного запроса также проверяют сохранение неактивных
товаров и вариантов (включая историческую цену без флагов ручного ввода/скидки),
восстановление их прежних цен при реактивации, явное
скрытие, отсутствие ложных событий удаления и работоспособность старой корзины.
